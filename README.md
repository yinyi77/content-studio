# 图文创作工作台

面向个人使用的本地 Web 应用。配置 OpenAI 兼容中转站，在对话里生成和修改图文；也可保存产品资料，由选题雷达主动发现宣传机会，批准后再制作。

## 当前界面

采用真实 Vben Admin 框架，使用官方 `@vben/layouts` 的侧边导航、顶部路径、访问页签、折叠布局和主题基础。业务包含创作对话、选题雷达、当下热点、账号管理、钉钉接入、作品记录和模型设置。正式地址为 http://127.0.0.1:4318/ 。

首版通过同源的单个持久工作区接入已有业务页面；Vben 负责外层布局与路由，现有 Node API、模型配置、作品和账号数据保持原有存储方式。切换外层路由不重建工作区，作品继续对话与未保存表单可保留上下文。业务页面暂未全部改写为 Vue 原生组件。官方来源、精简包清单和改动记录见 `frontend/UPSTREAM.json`，MIT 许可见 `frontend/LICENSE.VBEN`。

图片生成提供20种风格，支持在对话里按分类或关键词选择，也能直接说“写实摄影”“国风水墨”“黏土3D”等偏好。界面配色与生成风格独立；风格通过专门的视觉说明与整组共享规范传给已配置的模型，不会切换到额外的模型服务。

| 分类 | 图片风格 |
| --- | --- |
| 信息与排版 | 手绘知识、杂志编辑、醒目海报、工程蓝图、极简留白 |
| 生活与摄影 | 温暖生活、商业摄影、电影质感 |
| 艺术与质感 | 清透水彩、东方水墨、复古印刷、拼贴手账、剪纸叠层 |
| 插画与漫画 | 扁平矢量、漫画分镜、日系动画 |
| 立体与数字 | 黏土3D、等距3D、霓虹科技、像素游戏 |

原有6种风格保留原ID与参考；新增14种采用本地独立风格规则，分别约束媒介、光线或材质、构图和中文排版区。搜索可匹配风格名、描述及常用别名；分类、搜索和点选不会调用模型。

仓库仅包含应用源码、前端构建文件与必要文档，不包含个人模型配置、生成记录、本地界面备份和验证截图。首次启动后，在页面中填写自己的模型配置。

## 启动

需要 Node.js 20 或更新版本。首次运行及更新依赖后执行 `npm ci`，安装锁定的依赖（Nodemailer 用于邮件，官方 dingtalk-stream SDK 用于钉钉收消息）：

```bash
cd content-studio
npm ci
npm start
```

上面的 `content-studio` 替换为实际克隆目录。浏览器打开 http://127.0.0.1:4318 。macOS 也可在终端执行 `./启动工作台.command`。按 Ctrl+C 停止。

如果端口被占用，可以运行 `PORT=4319 npm start`，然后访问对应端口。

### 重建 Vben 前端

仓库包含已编译的 `frontend/dist`，日常 `npm start` 不需要额外启动前端开发服务。修改 `frontend/src` 或官方组件源码后执行：

```bash
npm run build:frontend
```

构建需要 pnpm，以及 Node.js 22.18+ 或 24.12+。构建脚本会使用当前受支持的 Node，或查找本机 NVM 中的可用版本；也可通过 `VBEN_NODE_BINARY` 指定。源码保留在项目目录，实际构建在隔离的 ASCII 临时目录进行，以兼容中文项目路径。重新构建完成后刷新页面即可。前端依赖与构建要求不改变 Node 20 后端的运行方式。

`/admin/` 为 Vben 入口别名，`/legacy?embedded=1&view=briefing` 为同源业务工作区；页面地址使用 `/#/briefing`、`/#/xhs` 等 hash 路由。静态资源仅从已编译的 `frontend/dist/assets` 提供。

## 首次配置

打开「模型设置」，分别填写文字和生图模型：

- **Base URL**：例如 `https://你的中转站域名/v1`。保留服务商指定的 API 前缀；不要填写中转站管理页面地址。
- **模型名称**：填写中转站实际开放的模型 ID。可以手动填写，也可保存后读取模型列表。
- **API Key**：在本地界面输入，不需要发到聊天里。两种模型可使用同一站点、同一 Key。
- **生图协议**：标准图片接口选 `Images`（`/images/generations`）；中转站通过聊天接口返回图片时选 `Chat`（`/chat/completions`）。
- **图片尺寸**：默认自动选择常见横竖尺寸；模型不接受时，按接口文档选择明确尺寸。

保存配置后可进行连接测试。文字测试会真实调用一次文字模型；生图测试会真实生成一张图片，可能产生费用。读取模型列表不代表模型一定可调用。

支持图片返回形式：Images 的 `data[].b64_json` / `data[].url`；Chat 的 `message.images`、图片 content 数组、Markdown 图片和图片 Data URL。不支持异步提交任务再轮询的专有生图协议；若中转站采用该方式，需要增加适配器。

## 使用

创作页采用最近作品列表与对话工作区，可搜索并继续已有作品。参数、追问、热点建议和图文结果都在同一条对话中展示，输入区固定在工作区底部，图片可直接粘贴或拖入。「交付设置」默认收起，原有自动送稿开关和目标账号保持可用；窄屏下通过作品记录继续查找作品。外层使用 Vben 统一导航与页签。

1. 默认进入「创作对话」，用一句话说想创作什么。文字模型会分析主题，给出表达方向和可结合的热点。
2. 如果缺少必要信息，助手会把问题集中在一条消息中，最多4项。一次回答即可；已经说过的信息不会重复询问，风格、比例或张数拿不准时可说「你定」。20种风格与参数选项仍保留在可展开的「创作方向与偏好」中。
3. 信息齐全后会自动完成内容方案和全部图片，默认保存在本平台，无需登录小红书。准备发布时，再在当前对话通过发布微服务送入小红书草稿。也可在创建前主动开启「生成后自动存小红书草稿」，开启后固定本次账号并自动完成首次送稿。无需再点击确认生成；第一句话足够清楚时直接开始。说「先别生成」或「只分析」会暂停，直到明确要求继续生成。仅回复「好的」不会视为补齐内容，也不会启动出图。
4. 图片、帖子标题、正文及实际进度直接出现在对话中。生成完成后可查看大图、复制正文、下载单图或打包下载；本地完成与小红书送稿分别显示，微服务返回草稿已核验后显示小红书交付完成。
5. 继续发送修改要求，例如「标题改成……」「第 2 张文字简洁一点」「重画第 1 张」「再给我 4 张配图」「补到 6 张」。帖子标题或正文的修改不重新生图；指定页修改仅重生受影响的图片；补图保留原有图片、标题和发布正文，只生成新增页，总数最多10张。单页封面也可补成多页图文。
6. 部分图片失败时，可以在对话中明确要求「重试失败图片」，只补未完成的页，包括未完成的新增配图。补图要求明确但模型只给出口头回复时，会最多追加一次文字请求修复方案；没有有效方案时明确提示尚未出图，不假报成功。刷新浏览器只恢复已有任务，不会重新提交付费调用；服务重启后中断的任务需要明确重试。
7. 作品记录保存已完成和未完成的任务。点击作品封面、标题或「继续对话」，即可回到对应作品的对话，查看结果、进度或继续修改。

打开已完成作品会先显示图片、复制文案和下载入口。下载整组时，ZIP 中的 `prompts/01.md` 等文件对应各图片版本在生成时使用的提示词。旧作品优先使用已有的页面记录。记录缺失时才按当前规则重建，ZIP 内的 `prompts/来源说明.md` 会标出旧版记录和重建的页码。

### 在输入框中发送产品图片

直接把图片粘贴或拖入聊天输入框，也可使用框内图片按钮选择文件。缩略图与文字在同一个输入框内，发送前可预览或移除；只发送图片时会进入产品宣传需求分析。每次创作最多4张参考图，单张最多8MB，支持静态PNG、JPEG、WebP。

添加图片只保存到本机，点击发送后才把原图交给已配置的文字模型分析；需求齐全后，策划和生图也会带上原图。用户确认的卖点优先，照片仅支持可见外观与清楚可读的文字，不用于推断功效、价格或未展示的功能。参考图随作品保留，刷新和后续重画会复用。生成后在一条消息中附新图并指定「第2张换成这张产品图」，只更新指定页的参考。

图片接口为Images模式时，有参考图走兼容的`/images/edits`图片编辑接口，无参考图沿用`/images/generations`；Chat模式使用`image_url`内容块。文字模型需支持图片理解，中转站需开放相应图片输入与参考图生成能力；不支持时保留素材与已有结果并显示错误，不会静默忽略图片或自动换接口重试。生成式参考不能保证包装文字与Logo逐像素一致，成品仍需检查。[OpenAI参考图接口说明](https://developers.openai.com/api/docs/guides/image-generation)、[DeepSeek图片输入说明](https://api-docs.deepseek.com/guides/vision/)。

原图与元数据保存在本地`data/reference-images/`；浏览器草稿仅保存图片编号和预览地址，不把Base64放进sessionStorage。生成请求和修改请求的去重信息包含图片，刷新或重试相同请求不会再次创建任务。参考图暂不自动清理，避免草稿或历史作品丢失素材。

## 钉钉对话创作

打开「钉钉接入」（`/?view=dingtalk`）。这是新增的独立入口，网页创作、雷达、热点、作品记录和小红书功能仍可照常使用。接入企业内部应用机器人，支持私聊和按需开启的群聊，默认不连接、不接收消息。新安装与旧配置的群聊开关默认关闭。

1. 在钉钉开发者后台创建企业内部应用，添加机器人能力，接收模式选择 **Stream**，发布应用并设置本人可见。根据实际接口开通机器人发送私聊／群聊、消息附件下载与媒体上传所需权限。需要管理员或开发者权限。[官方创建教程](https://open-dingtalk.github.io/developerpedia/docs/explore/tutorials/stream/bot/java/create-bot/)
2. 在本平台填写 Client ID（AppKey）、Client Secret（AppSecret）、Robot Code、企业 Corp ID 和允许使用的员工 User ID。编号从组织/应用配置取得，不能用手机号或昵称代替。首期建议只允许本人；企业、机器人和发送人都会校验。
3. 点击「保存配置」，再「验证凭证」。凭证验证只获取应用 AccessToken，不发送钉钉消息、不调用模型；通过不代表消息与媒体权限已经全部验证。
4. 点击「连接钉钉」，等待实际连接状态。在钉钉找到应用机器人，私聊直接发送需求；缺少信息时集中追问一次，补充后自动调用现有模型完成文案和整组图片。也可先发产品图片，再发文字需求。每次最多4张静态参考图，单张最多8MB。纯问候由本地回应，不调用模型、不占用集中追问的一轮。
5. 成品通过钉钉媒体上传与对应消息接口回传，包含帖子标题、正文和按顺序排列的图片；同时保存在平台「作品记录」。可以继续说「标题改成……」「第2张重新画」「再补2张」，沿用同一作品。新主题请发「新建创作」；需要状态时发「查看进度」。

**在群里使用**：把应用机器人加入同一组织的企业内部群，开启本页「允许在群聊中创作」并保存，再重新连接。需求、补充回答和后续修改每次都需通过钉钉的 @ 功能选中机器人。仅接收白名单成员、同组织且确实 @ 机器人的群消息；群里普通聊天不会触发模型调用。[官方接收规则](https://open-dingtalk.github.io/developerpedia/docs/learn/bot/appbot/receive/)

群消息的文案与图片回到发起请求的原群，使用应用 AccessToken 的群聊发送接口，长任务不依赖临时 sessionWebhook；群发送失败会保留结果，不改投私聊。私聊仍回私聊。上下文按组织、机器人、会话和发送人隔离：同一人在不同群或私聊分别创作，同群其他成员不能直接修改你的当前作品。会话及回传记录显示群聊／私聊与群名称，交付快照固定原目标，补发不会更换群。[官方群发送接口](https://open.dingtalk.com/document/orgapp/the-robot-sends-a-group-message)

群内产品图也必须属于机器人实际收到的带 @ 消息。先普通发送图片、再单独 @ 机器人，不能自动补取之前的图片。群聊关闭后不会接收或补发群任务；重新开启、刷新或重启不会补跑此前被忽略的群消息。

Stream 由本机主动建立连接，无需公网回调域名、开放端口或内网穿透；运行电脑必须保持在线且服务持续运行。给钉钉回传的是实际内容和媒体，不发送手机无法访问的 localhost 结果链接。[官方 Stream 说明](https://open-dingtalk.github.io/developerpedia/docs/learn/stream/overview/)、[官方媒体说明](https://open-dingtalk.github.io/developerpedia/docs/learn/stream/faq/)

消息先落盘再确认接收，按消息编号去重，生成在后台执行。服务重启不会自动连接、重跑模型或重发旧消息；中断任务可在重新连接后明确回复「继续上次任务」。结果回传明确失败时可以补发未受理部分，不重新出图；受理未知的消息不自动重发。接口受理不等于客户端最终展示，真实应用仍需配置后联调。图片在平台生成成功与钉钉发送成功分别记录。

Secret 仅保存在本机 `data/dingtalk.json`（文件权限600），不会返回给网页或写入模型提示词；空白保存保留原密钥，更换 Client ID 需要重填。保存配置会先断开旧连接，需手动重新连接。会话、接收去重与交付记录保存在 `data/dingtalk-state.json`，待发图片快照位于 `data/dingtalk-outbox/`，均不进入 Git 或作品导出包。收到的需求、参考图仍按正常创作流程发送给用户配置的模型服务。

首版不自动开启每日热点提案推送，也不自动送入小红书或公开发布。已有小红书功能可在平台继续使用。

## 账号管理与小红书发布微服务

工作台负责创作和保存作品。账号登录、草稿写入及平台结果核验全部由独立发布微服务执行。工作台通过服务端 REST API 提交草稿，保存回执并查询进度。首次使用时请向服务方取得实际地址、账号 ID 和服务令牌。

1. 在项目目录执行 `cp -n .env.example .env.xhs-publisher` 和 `chmod 600 .env.xhs-publisher`，用本机编辑器打开新文件。填写服务地址、服务方配置的账号 ID 和服务方提供的 `XHS_API_TOKEN` 原值。工作台对应的令牌字段叫 `XHS_PUBLISHER_TOKEN`。该文件已由 Git 忽略。
   如果服务方提供的是以 `/v1/jobs` 结尾的 cURL，请把该路径之前的地址填入 `XHS_PUBLISHER_BASE_URL`。异机部署可以先只填服务地址、账号和令牌，重启后即可检查服务和读取草稿。配置可用图源后再启用送稿。
2. 确认**微服务的 worker 能下载工作台生成的图片**。同一台机器且共享网络命名空间时可使用默认的回环地址。分机部署可按下文配置内网临时链接。已有图片站点也可单独设置 `XHS_PUBLISHER_MEDIA_BASE_URL`，让站点提供 `/media/<作品编号>/<版本化文件名>`，并把站点域名加入微服务的图片白名单。
3. 重启工作台（`npm start` 或原启动脚本，配置文件支持 Node.js 20.12+）。进入「账号管理」，打开送稿账号，在草稿箱检查服务连接。就绪检查会核对令牌、账号、数据库、worker 和暂停状态。服务端的预约发布开关可以保持关闭。
4. 在创作对话选择生成后存草稿，或进入「账号管理」中该账号的草稿箱，选择一份已完成的作品送稿。工作台保存本次请求的幂等键和回执，按原图顺序提交。只有创建任务成功、草稿已就绪且平台状态核验通过，才显示交付完成。草稿箱按账号展示微服务跟踪的草稿，可查看标题、正文、图片数量和状态。
5. 写完再选账号时，在创作结果或「作品记录」点「选择账号并发布」。选中目标账号，核对图文并存入草稿箱。每个账号独立保存送稿回执。
6. 草稿核验后可按北京时间预约。微服务需为目标账号开启预约发布，并启用 API 和 worker 的发布开关。选好时间并确认账号、标题和版本后，工作台会记录审批并提交预约。默认需提前 65 分钟，可选未来 14 天内的时间，具体提前量以服务配置为准。重新打开同一份草稿可查看原预约进度，平台核对成功后显示「已预约发布」。
7. v0.5.0 在「账号管理 → 账号数据」提供累计粉丝、关注、获赞与收藏，以及近 7 天和近 30 天的观看、互动、涨粉和发布指标。「已发布内容」逐篇列出浏览、点赞、评论、收藏和分享。打开页面读取已有缓存，点击同步后才启动对应任务。
8. 在「账号管理 → 草稿箱」打开服务登记的草稿，可以预览当前配图并修改原稿。只改标题或正文时沿用原图，换图时可以选择作品记录中的整组配图或填写图片链接。修改核验后版本递增。预约需再次核对当前已验证的帖子和图片。

工作台重启后只查询已受理的任务。旧版保存在本机的账号、浏览器会话、草稿缓存和送稿回执留在原数据目录；工作台不会读取旧会话、迁移凭证或重新送出历史草稿。服务未配置或暂停时仍可在工作台创作、修改和下载作品。

### 两台公司内网机器之间传图

假设工作台电脑是 `192.168.1.20`，运行下载任务的 worker 是 `192.168.1.30`。部署时换成实际地址。

1. 在工作台的 `.env.xhs-publisher` 设置 `XHS_PUBLISHER_LAN_MEDIA_ORIGIN=http://192.168.1.20:8766` 和 `XHS_PUBLISHER_WORKER_IP=192.168.1.30`，重启工作台。worker 地址应填写工作台实际看到的取图来源 IP。内网防火墙需允许该来源连接工作台 TCP 8766。
2. 在微服务配置的 `XHS_IMAGE_ALLOWED_HOSTS` 中保留原条目，追加工作台的 IP（示例为 `192.168.1.20`），并设置 `XHS_IMAGE_ALLOW_PRIVATE=true`。用更新后的配置重启微服务 API 和 worker。在「账号管理」中打开送稿账号的草稿箱，点击「检查服务」，工作台会读取服务报告的白名单。
3. 在创作对话里照常送稿。工作台为选中的图片生成 24 小时链接，首图为封面。工作台本机可直接在浏览器打开同一个链接预览，指定的 worker 按作品顺序下载。取图期间请保持工作台在线。图片端口通过连接来源 IP 限定这两台机器，管理页面继续使用本机回环地址。

作品图片的版本和顺序会随送稿记录一起保存。遇到可重试的下载失败时，使用原记录重试可为同一组图片续期并沿用原 URL 与幂等记录。原文件发生变更时，需要确认作品的新版本后再送稿。

服务方可参考[微服务接口评审](docs/xhs-publisher-api-review.md)，查看 v0.1.0 已具备的操作和建议补充的接口。

## 主动选题与通知

打开「选题雷达」（`/?view=radar`），按以下顺序配置：

1. **产品与行业资料**：保存主产品、目标用户、真实卖点和宣传目标。可添加最多20份工具案例或行业资料，直接粘贴文本或导入 UTF-8 TXT / Markdown；正文总计最多10万字。每份案例可附最多4张独立截图，全局另存品牌与通用参考图。选题制作只带所选案例的截图，优先案例图，去重后连同通用图最多4张。没有自动读取 URL 正文、PDF 或本地整个目录。
2. **现在巡查**：先抓取微博、抖音、小红书公开热榜，按新鲜度筛选，再用一次文字模型评估与产品的关联。每轮及每日最多3条提案，没有合适关联时返回零条。不同平台的热度数字不直接比较，本机榜内名次变化也不等同流量预测。
3. **选题通知**：首选 SMTP 邮箱，填写服务器、用户名、授权码、发件与收件邮箱。支持465 TLS或587 STARTTLS。保存后可点「发送测试通知」，该按钮会真实发送一条消息。可选 PushPlus，将提醒发送至绑定的个人微信；需要自行绑定该服务，投递受其规则与额度限制。
4. **自动巡查**：指定每天的北京时间与默认图片规格后开启。默认关闭，不会在安装后自动消耗模型额度。定时运行同样先抓取热点。停止服务或电脑休眠时不会运行；重启不会补发错过的付费选题任务。
5. **批准制作**：在网页或邮件决策页查看热点来源、产品关联、案例、提纲与规格，点「就做这篇 / 批准并生成」后才创建作品并生成全部图文；完成或部分失败后发送一次结果通知。跳过、打开链接与刷新页面不生成图片。重复批准复用同一个作品，不自动再次收费。

雷达页显示设置完成度、当日巡查/提案/批准/图文完成数，以及批准后的图片进度；生成和通知发送中会自动更新，不打断正在编辑的资料或跳过说明。完成时间按图片真正完成的北京时间计算，修改帖子正文不计为重新完成。最近60次巡查记录保存在本机，包含成功、失败和中断；修改配置或重启不会补跑旧任务。

**偏好反馈**：跳过时可选「关联较弱」「不符合产品定位」「做过了」「时机不合适」或写简短说明，也可直接跳过。后续巡查把最近30条简要批准/跳过记录作为选题参考，不把批准当成已经验证的传播效果，反馈也不能覆盖产品事实。

**通知记录与补发**：选题、完成及测试通知的服务商受理状态与尝试次数可在页面查看。明确失败或未配置而跳过的通知，在配置好之后可手动重新发送，单条最多5次手动重试；已受理、受理未知和正在发送的消息不提供重发。补发选题需仍在有效期且未决策，补发结果不会重新生图。修改邮箱配置本身不会自动补发历史消息。

如果主营模型 API 中转站，可将其设为主产品，把不同 coding 小工具作为案例分别录入。雷达按每个热点召回贴合的资料片段，固定本次引用的案例与产品版本，用实际应用场景引导了解中转站；不会把多个作品的功能混成一个产品。模型提示词约束不得编造价格、模型权限、速度、稳定性或案例效果，最终发布前仍应检查事实与图中文字。

热梗库仍保留首次收录后14天的有效期。提案采用更短的制作窗口：普通热点受源更新时间2小时、本机采集1小时与6小时提案上限共同限制；热梗提案最多24小时且不超过其14天截止日。批准时会重新检查当前来源与产品资料版本。资料更新后旧待决策提案失效，已有作品保持原资料快照。

**手机上决策**：默认通知链接指向这台电脑的 `127.0.0.1`，只能在本机打开。需要手机访问时，先自行配置 HTTPS 反向代理或隧道，再填写「手机决策链接的服务地址」（只填域名根地址，无路径）。代理只开放 `/decision/` 路径并保留原始 Host，其他路径一律拒绝；不要将整个本地工作台直接公开。服务仍只监听 `127.0.0.1`，且只允许配置域名访问签名决策路径，模型配置与全量作品 API 不对外开放。此项目没有自动创建公网隧道或托管部署。

决策链接仅授权一份提案，有效24小时；提案本身过期后不能借链接新建创作。批准操作需在决策页提交 POST，邮件预览和安全扫描不会触发制作。链接持有人能查看该提案、批准制作及查看其结果，请按私人链接使用。 SMTP / PushPlus「受理」不等同最终送达；网络中断时标记结果未知，不自动重发。通知失败不删除已保存提案或作品。

抓榜不使用模型额度，巡查分析使用文字模型，批准制作使用文字与图片模型。参考图仍需所配置的中转站支持图片理解与参考图生图；收到上游502或端点不支持时会保留任务和原图，不会自动换端点或忽略参考图。

## 当下热点

打开导航中的「当下热点」，或直接访问 http://127.0.0.1:4318/#/trends 。页面以表格汇总微博、抖音、小红书的公开热榜，集中展示榜内排名、话题、来源、平台热度与采集时间，支持平台筛选、标题搜索、关注词与热梗筛选，并可点击「用于创作」带入对话。关键词、采集间隔、暂停开关及来源详情位于「采集设置」窗口，打开窗口和调整列表筛选不会调用模型。关注词只匹配当前已采集的榜单，不是全平台内容搜索；未出现在榜单的热梗可能无法找到。「热梗候选」是标题规则筛选出的线索，不代表已经核实梗的含义或来源。

默认每 30 分钟更新，可改为 15／30／60 分钟，也可暂停或手动刷新。定时任务由本机 Node 服务运行，关闭浏览器仍能更新；停止服务、电脑关机或休眠时不会持续采集。重新启动后会按缓存状态补刷新。抓榜不调用模型；「带入创作」只准备输入，发送分析后才会调用已配置的文字模型。

数据通过第三方公开聚合接口读取：首选 [UAPI 热榜接口](https://uapis.cn/docs/api-reference/get-misc-hotboard)，备用为 [60s API](https://github.com/vikiboss/60s) 的微博、抖音和 [小红书热榜](https://docs.60s-api.viki.moe/344628918e0)。当前匿名接口无需提交模型密钥；第三方可能限流、变更服务或更新延迟，不保证长期可用。60s 主实例有每日额度限制，长期使用建议部署自己的实例。应用没有登录社媒账号，也不采集登录后的笔记正文、视频、评论或个人资料。

页面分别展示「本机采集时间」与「源榜单更新时间」：源榜单超过 2 小时会标为延迟，无源时间则标为未知；采集失败时保留上次结果并显示原因。2026-10-29 接入验证时，小红书有来源返回两天前的榜单，因此不能只看请求成功就当作实时热点。原始榜单用于发现选题，创作前请打开原话题核实语境。

若已自部署 60s，可设置 `TRENDS_60S_BASE_URL=https://你的实例域名 npm start` 更换备用实例（地址不带 `/v2`）。该设置不改变 UAPI 主源；首次接入不需要额外部署服务。

需求对话、输入、确认参数和当前作品关联保存在当前标签页的 `sessionStorage` 中；关闭标签页后可能清除，作品和生成后的修改记录仍由本机服务保存。需求分析通过 `/api/brief/chat` 完成；服务端校验 ask/generate/hold 决策，前端仅在收到新的有效 generate 响应时通过 `/api/brief/create` 启动后台策划和出图。旧模型缺少决策、无实质回答或明确暂停时不自动出图。刷新只恢复已有任务，不会根据保存的决策重发生成。生成后的自然语言修改通过作品的 `/chat` 接口处理。发送分析或修改会使用文字模型，生成和重画会使用图片模型；快捷参数选择、查看结果、复制和下载不调用模型。创建和修改请求使用唯一编号防止同一请求重复执行；重试需要用户明确发起。

### 按创作需求匹配热点

创作对话默认开启「帮我匹配相关热点」。发送需求后，文字模型在同一次分析中，从已采集的有效热榜中按主题、受众和创作目标寻找关联，最多推荐 3 个话题，并解释「为什么相关」与「结合角度」。没有合适的话题时可以直接按原需求继续，也可以关闭匹配。热点候选会增加本次文字请求的输入内容，但不会为每个候选分别调用模型。

点击某个话题的「结合这个热点」后，该话题及结合角度才会在明确生成时写入素材；只会加入所选的一个话题，不会把整个推荐列表塞入方案。选择、取消和参数快捷选项均不调用模型。重新匹配或发送自然语言补充仍会使用一次文字模型；匹配失败不会阻止原有创作流程。

普通热点的自动推荐排除过期、来源时间未知或本次抓取失败的榜单，并限制本机采集时间在 1 小时以内；热梗候选使用下述 14 天留存规则。推荐只依据热榜标题和已有摘要，不会读取链接正文，也不能替代对热梗含义、来源和时效的核实。选择后的策划以原需求为主体，将热点作为适合的切入方式，不凭标题编造事实。

### 热梗库的 14 天有效期

带有挑战、玩梗、表情包等标题特征的话题会作为「热梗候选」收录进本机热梗库。从本机首次收录起计算 14 天，重复采集不会延长有效期；掉出当前热榜后仍可在有效期内查看并参与需求匹配。页面显示收录时间与截止日期，过期后不再推荐，已选候选在恢复或交接时也会检查有效期。普通新闻热点不会因此延长到 14 天。

这 14 天是应用的留存与选题使用期限，不是热梗真实起源时间，也不表示该话题一直在热榜上。标题规则只能识别候选；自动匹配仍要求有可核验的来源时间，不能用本机新抓取的时间将来源已过期的数据包装成新热梗。

### 文案与画面方案

文案生成先整理素材中的已知事实、读者问题、内容目的和用户口吻，再选择有依据的表达角度。可在创作对话里附喜欢的文案或自己的文章作为口吻样例，样文仅提供表达习惯。中文编辑规则改编自 MIT 许可的 [Humanizer-zh](https://github.com/op7418/Humanizer-zh)，随项目固定保存在 `vendor/humanizer-zh/`。

初稿完成后，使用当前配置的文字模型发起独立审稿请求，检查帖子标题、发布正文和图内文字。五项满分分别为素材一致30、信息价值25、自然表达25、读者适配10、内容目的10。初始通过线为80分，前三项分别至少24、18、18分；无依据的产品承诺、经历或违背明确要求的遗漏会阻止通过。分数属于内部编辑评估，不代表作者身份、事实核验或传播效果。

未通过或存在具体编辑建议时按意见自动返修，最多两轮，每轮重新评分；通过后才出图。后续润色变差或失败时可采用此前已通过的版本。尚无合格版本且审稿异常或仍未合格时，保留文字草稿并提示调整，暂停本次后续出图及自动送稿。正文改稿和补图同样审阅本次文字，未指定的文字不参与自动返修；只重画已有图片时，若需要首次审稿只做检查。对话结果可展开查看分项、问题与优化轮次。通常增加一次文字审稿，返修会额外调用文字模型；仅查看、刷新或重启不会重跑审稿。

发布标题和正文按知识分享、产品介绍、观点或生活内容分别组织，减少空泛套话与强行互动，不编造产品参数、使用经历或热点细节。缺少关键素材时，创作对话会集中一次询问。用户交给助手决定的视觉偏好可采用建议值；未知的产品事实仍不会编造。策划说明与素材缺口单独保存，并在生成后的对话里说明，不由服务端拼入发布正文或图上文字。

新方案会为整组图片生成共享视觉规范（配色、字体气质、插画语言与布局），再为每页编写构图、阅读顺序和准确文字。生图时以当前页的标题和正文为准，避免旧提示词里的文字在修改后重新出现。旧作品没有共享规范时使用对应风格的默认规范；用户明确要求的本页视觉调整仍可覆盖相关默认维度。

视觉策划按内容选择具体的主体、媒介和图文关系，整组统一配色、字体与笔触，封面、物件图鉴、生活场景和步骤页可以采用不同构图。「手绘知识」默认采用独立刊物式的细笔生活插画、清楚的中文印刷字与一种专色。普通知识页直接使用整张画幅，减少悬浮圆角白卡、投影、粗黑漫画字、荧光条和彩色圆底图标等固定组合。新版美术指导仅描述画面，图内文字由当前字段单独传入；读取旧作品提示词时会剔除独立的旧文字清单。

「商业摄影」采用自然日常摄影与产品排版：具体说明环境、视角与景别、主光方向、材质和文字空间，减少塑料高光、过度锐化、全息图标和重复桌面摆拍。软件与API推广未选风格时优先建议此方向，明确选择的其他风格仍优先。没有截图或产品照片时可生成中性概念场景，不要求为了写实补交图片，也不把虚构UI、代码、调用数据或生成场景当作真实产品证据。同样的写实约束用于策划、生图与后续聊天改图；提示词改善不代表能保证生成图完全没有模型痕迹。

通过聊天修改图片内文字或画面描述时，只重画受影响的页面。共享文字规范能减少风格漂移，但尚未实现跨页参考图或真实产品外观锁定，也不能保证模型逐字正确排版。图片中文字出错时，可精简文字或更换模型后重画。

选择的比例为构图目标，实际像素尺寸由模型及尺寸参数决定。标准 Images 接口的兼容尺寸为方形 1024×1024、竖版 1024×1536、横版 1536×1024。支持相应尺寸的模型可在「模型设置 → 图片模型 → Images 请求尺寸」选择「按目标比例请求」，竖版请求 1152×1536、横版请求 1536×864。Chat 接口通过提示词传达比例。每张成品都显示目标比例与实际像素及比例，旧作品打开时从已载入的图片读取。

## 数据和模型资源

配置与作品都在应用的 `data/` 目录：

```text
data/
  config.json              # 本机模型设置，含明文 Key，文件权限 600
  trends.json              # 热榜缓存、14天热梗库、刷新设置与关注词，不含模型密钥
  radar.json               # 产品资料、资料版本、选题提案和每日任务记录
  notifications.json       # SMTP / PushPlus 设置与授权码，文件权限 600
  notification-outbox.json # 通知受理与去重记录，文件权限 600
  decision-link-secret     # 提案签名链接密钥，文件权限 600
  dingtalk.json            # 钉钉应用凭证与使用范围，文件权限 600
  dingtalk-state.json      # 钉钉会话、消息去重与交付记录，文件权限 600
  dingtalk-outbox/         # 回传图片冻结快照，不含应用凭证
  reference-images/        # 产品参考图与元数据
  xhs-publisher/           # 按服务地址与账号隔离的送稿记录，含冻结请求与任务回执
  projects/<作品编号>/
    project.json           # 原始素材、拆页方案、状态和记录
    prompts/               # 实际发送到生图模型的完整提示词
    images/                # 下载到本机的模型图片
```

后端只监听本机回环地址。保存过的 Key 不会回传给网页，也不会写入作品导出包。更换中转站域名时需要重新输入 Key。不要分享 `data/` 配置文件；该目录已列入 `.gitignore`。

素材和提示词会发送给你配置的模型服务，图片 URL 会由本机后端下载。应用没有托管服务器，没有内置 API Key，也不会自动使用聊天账号额度。

## 技术结构

- 前端：原生 HTML / CSS / JavaScript，创作对话、选题雷达、当下热点、账号管理、钉钉接入、作品记录、模型设置七个视图，同源调用后端。创作、预览、修改和下载统一在对话中完成。
- 后端：Node.js 内置 HTTP 服务、Fetch 与文件系统；SMTP 邮件使用 Nodemailer，小红书草稿通过发布微服务的 REST API 提交和查询；钉钉使用官方 Stream SDK 接收及固定 OpenAPI 端点回复。
- 持久化：按作品保存 JSON，使用临时文件加原子替换写入。
- 任务：每个作品后台异步执行；图片逐张生成；最多两个作品任务同时运行。
- 热点：独立后台定时采集、失败保留缓存，同平台话题去重，关注词与定时设置保存在本机。测试可设 `TRENDS_AUTO_REFRESH=0` 禁止自动外部请求。
- 首版不包含多人账号、社媒自动发布、拖拽画布与原生可编辑图层。

## 与 baoyu-skills 的关系

本项目是独立的 Web 适配实现，真实复用 `baoyu-skills` 的内容分析、提示词组织和六套风格参考。没有运行完整的官方 Agent 工作流，也不属于官方 GUI。

上游仓库：https://github.com/JimLiu/baoyu-skills

固定版本及文件清单见 `vendor/baoyu-skills/SOURCE.json`，原 MIT 许可证见 `vendor/baoyu-skills/LICENSE`。修改上游提示词前建议保留版本记录。模型服务及其生成内容按对应服务条款使用。
