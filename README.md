# 图文创作工作台

面向个人使用的本地 Web 应用。配置 OpenAI 兼容中转站，即可完成「输入素材 → AI 拆页 → 修改方案 → 生成图片 → 下载作品」。

## 当前界面

采用雾白、石墨灰与深蓝的单列创作对话：一句话发起，按需一次集中补充，然后自动生成文案与整组图片。顶部保留创作对话、当下热点、作品记录和模型设置。生成后可查看大图、复制帖子正文或下载作品。正式地址为 http://127.0.0.1:4318/ 。

图片生成提供20种风格，支持在对话里按分类或关键词选择，也能直接说“写实摄影”“国风水墨”“黏土3D”等偏好。界面配色与生成风格独立；风格通过专门的视觉说明与整组共享规范传给已配置的模型，不会切换到额外的模型服务。

| 分类 | 图片风格 |
| --- | --- |
| 信息与排版 | 手绘知识、杂志编辑、醒目海报、工程蓝图、极简留白 |
| 生活与摄影 | 温暖生活、商业摄影、电影质感 |
| 艺术与质感 | 清透水彩、东方水墨、复古印刷、拼贴手账、剪纸叠层 |
| 插画与漫画 | 扁平矢量、漫画分镜、日系动画 |
| 立体与数字 | 黏土3D、等距3D、霓虹科技、像素游戏 |

原有6种风格保留原ID与参考；新增14种采用本地独立风格规则，分别约束媒介、光线或材质、构图和中文排版区。搜索可匹配风格名、描述及常用别名；分类、搜索和点选不会调用模型。

仓库仅包含应用源码与必要文档，不包含个人模型配置、生成记录、本地界面备份和验证截图。首次启动后，在页面中填写自己的模型配置。

## 启动

需要 Node.js 20 或更新版本，无需安装 npm 依赖。

```bash
cd content-studio
npm start
```

上面的 `content-studio` 替换为实际克隆目录。浏览器打开 http://127.0.0.1:4318 。macOS 也可在终端执行 `./启动工作台.command`。按 Ctrl+C 停止。

如果端口被占用，可以运行 `PORT=4319 npm start`，然后访问对应端口。

## 首次配置

打开「模型设置」，分别填写文字和生图模型：

- **Base URL**：例如 `https://你的中转站域名/v1`。保留服务商指定的 API 前缀；不要填写中转站管理页面地址。
- **模型名称**：填写中转站实际开放的模型 ID。可以手动填写，也可保存后读取模型列表。
- **API Key**：在本地界面输入，不需要发到聊天里。两种模型可使用同一站点、同一 Key。
- **生图协议**：标准图片接口选 `Images`（`/images/generations`）；中转站通过聊天接口返回图片时选 `Chat`（`/chat/completions`）。
- **图片尺寸**：默认自动选择常见横竖尺寸；模型不接受时，按接口文档选择明确尺寸。

保存配置后可进行连接测试。文字测试会真实调用一次文字模型；生图测试会真实生成一张图片，可能产生费用。读取模型列表不代表模型一定可调用。

支持图片返回形式：Images 的 `data[].b64_json` / `data[].url`；Chat 的 `message.images`、图片 content 数组、Markdown 图片和图片 Data URL。不支持异步提交任务再轮询的专有生图协议；若中转站采用该方式，需要增加适配器。

## 使用

界面采用单列创作对话，参数、热点建议和图文结果都在同一条对话中展示；导航、热点、作品记录及模型设置统一使用雾白与深蓝配色。

1. 默认进入「创作对话」，用一句话说想创作什么。文字模型会分析主题，给出表达方向和可结合的热点。
2. 如果缺少必要信息，助手会把问题集中在一条消息中，最多4项。一次回答即可；已经说过的信息不会重复询问，风格、比例或张数拿不准时可说「你定」。20种风格与参数选项仍保留在可展开的「创作方向与偏好」中。
3. 信息齐全后会自动完成内容方案和全部图片，无需再点击确认生成；第一句话足够清楚时直接开始。说「先别生成」或「只分析」会暂停，直到明确要求继续生成。仅回复「好的」不会视为补齐内容，也不会启动出图。
4. 图片、帖子标题和正文会直接出现在对话中。生成时显示进度，完成后可查看大图、复制正文、下载单图或打包下载。
5. 继续发送修改要求，例如「标题改成……」「第 2 张文字简洁一点」「重画第 1 张」。帖子标题或正文的修改不重新生图；指定页修改仅重生受影响的图片。
6. 部分图片失败时，可以在对话中明确要求「重试失败图片」，只补未完成的页。刷新浏览器只恢复已有任务，不会重新提交付费调用；服务重启后中断的任务需要明确重试。
7. 作品记录保存已完成和未完成的任务。点击作品封面、标题或「继续对话」，即可回到对应作品的对话，查看结果、进度或继续修改。

### 在输入框中发送产品图片

直接把图片粘贴或拖入聊天输入框，也可使用框内图片按钮选择文件。缩略图与文字在同一个输入框内，发送前可预览或移除；只发送图片时会进入产品宣传需求分析。每次创作最多4张参考图，单张最多8MB，支持静态PNG、JPEG、WebP。

添加图片只保存到本机，点击发送后才把原图交给已配置的文字模型分析；需求齐全后，策划和生图也会带上原图。用户确认的卖点优先，照片仅支持可见外观与清楚可读的文字，不用于推断功效、价格或未展示的功能。参考图随作品保留，刷新和后续重画会复用。生成后在一条消息中附新图并指定「第2张换成这张产品图」，只更新指定页的参考。

图片接口为Images模式时，有参考图走兼容的`/images/edits`图片编辑接口，无参考图沿用`/images/generations`；Chat模式使用`image_url`内容块。文字模型需支持图片理解，中转站需开放相应图片输入与参考图生成能力；不支持时保留素材与已有结果并显示错误，不会静默忽略图片或自动换接口重试。生成式参考不能保证包装文字与Logo逐像素一致，成品仍需检查。[OpenAI参考图接口说明](https://developers.openai.com/api/docs/guides/image-generation)、[DeepSeek图片输入说明](https://api-docs.deepseek.com/guides/vision/)。

原图与元数据保存在本地`data/reference-images/`；浏览器草稿仅保存图片编号和预览地址，不把Base64放进sessionStorage。生成请求和修改请求的去重信息包含图片，刷新或重试相同请求不会再次创建任务。参考图暂不自动清理，避免草稿或历史作品丢失素材。

## 当下热点

打开顶部的「当下热点」，或直接访问 http://127.0.0.1:4318/?view=trends 。页面汇总微博、抖音、小红书的公开热榜，支持平台筛选、标题搜索、关注关键词，以及将选题带入创作对话。关注词只匹配当前已采集的榜单，不是全平台内容搜索；未出现在榜单的热梗可能无法找到。「热梗候选」是标题规则筛选出的线索，不代表已经核实梗的含义或来源。

默认每 30 分钟更新，可改为 15／30／60 分钟，也可暂停或手动刷新。定时任务由本机 Node 服务运行，关闭浏览器仍能更新；停止服务、电脑关机或休眠时不会持续采集。重新启动后会按缓存状态补刷新。抓榜不调用模型；「带入创作」只准备输入，发送分析后才会调用已配置的文字模型。

数据通过第三方公开聚合接口读取：首选 [UAPI 热榜接口](https://uapis.cn/docs/api-reference/get-misc-hotboard)，备用为 [60s API](https://github.com/vikiboss/60s) 的微博、抖音和 [小红书热榜](https://docs.60s-api.viki.moe/344628918e0)。当前匿名接口无需提交模型密钥；第三方可能限流、变更服务或更新延迟，不保证长期可用。60s 主实例有每日额度限制，长期使用建议部署自己的实例。应用没有登录社媒账号，也不采集登录后的笔记正文、视频、评论或个人资料。

页面分别展示「本机采集时间」与「源榜单更新时间」：源榜单超过 2 小时会标为延迟，无源时间则标为未知；采集失败时保留上次结果并显示原因。2026-10-29 接入验证时，小红书有来源返回两天前的榜单，因此不能只看请求成功就当作实时热点。原始榜单用于发现选题，创作前请打开原话题核实语境。

若已自部署 60s，可设置 `TRENDS_60S_BASE_URL=https://你的实例域名 npm start` 更换备用实例（地址不带 `/v2`）。该设置不改变 UAPI 主源；首次接入不需要额外部署服务。

需求对话、输入、确认参数和当前作品关联保存在当前标签页的 `sessionStorage` 中；关闭标签页后可能清除，作品和生成后的修改记录仍由本机服务保存。需求分析通过 `/api/brief/chat` 完成；服务端校验 ask/generate/hold 决策，前端仅在收到新的有效 generate 响应时通过 `/api/brief/create` 启动后台策划和出图。旧模型缺少决策、无实质回答或明确暂停时不自动出图。刷新只恢复已有任务，不会根据保存的决策重发生成。生成后的自然语言修改通过作品的 `/chat` 接口处理。发送分析或修改会使用文字模型，生成和重画会使用图片模型；快捷参数选择、查看结果、复制和下载不调用模型。创建和修改请求使用唯一编号防止同一请求重复执行；重试需要用户明确发起。

### 按创作需求匹配热点

创作对话默认开启「帮我匹配相关热点」。发送需求后，文字模型在同一次分析中，从已采集的有效热榜中按主题、受众和创作目标寻找关联，最多推荐 3 个话题，并解释「为什么相关」与「结合角度」。没有合适的话题时可以直接按原需求继续，也可以关闭匹配。热点候选会增加本次文字请求的输入内容，但不会为每个候选分别调用模型。

点击某个话题的「结合这个热点」后，该话题及结合角度才会在明确生成时写入素材；只会加入所选的一个话题，不会把整个推荐列表塞入方案。选择、取消和参数快捷选项均不调用模型。重新匹配或发送自然语言补充仍会使用一次文字模型；匹配失败不会阻止原有创作流程。

普通热点的自动推荐排除过期、来源时间未知或本次抓取失败的榜单，并限制本机采集时间在 1 小时以内；热梗候选使用下述 14 天留存规则。推荐只依据热榜标题和已有摘要，不会读取链接正文，也不能替代对热梗含义、来源和时效的核实。选择后的策划以原需求为主体，将热点作为适合的切入方式，不凭标题编造事实。

### 热梗库的 14 天有效期

带有挑战、玩梗、表情包等标题特征的话题会作为「热梗候选」收录进本机热梗库。从本机首次收录起计算 14 天，重复采集不会延长有效期；掉出当前热榜后仍可在有效期内查看并参与需求匹配。页面显示收录时间与截止日期，过期后不再推荐，已选候选在恢复或交接时也会检查有效期。普通新闻热点不会因此延长到 14 天。

这 14 天是应用的留存与选题使用期限，不是热梗真实起源时间，也不表示该话题一直在热榜上。标题规则只能识别候选；自动匹配仍要求有可核验的来源时间，不能用本机新抓取的时间将来源已过期的数据包装成新热梗。

### 文案与画面方案

发布标题和正文按知识分享、产品介绍、观点或生活内容分别组织，减少空泛套话与强行互动，不编造产品参数、使用经历或热点细节。缺少关键素材时，创作对话会集中一次询问。用户交给助手决定的视觉偏好可采用建议值；未知的产品事实仍不会编造。策划说明与素材缺口单独保存，并在生成后的对话里说明，不由服务端拼入发布正文或图上文字。

新方案会为整组图片生成共享视觉规范（配色、字体气质、插画语言与布局），再为每页编写构图、阅读顺序和准确文字。生图时以当前页的标题和正文为准，避免旧提示词里的文字在修改后重新出现。旧作品没有共享规范时使用对应风格的默认规范；用户明确要求的本页视觉调整仍可覆盖相关默认维度。

通过聊天修改图片内文字或画面描述时，只重画受影响的页面。共享文字规范能减少风格漂移，但尚未实现跨页参考图或真实产品外观锁定，也不能保证模型逐字正确排版。图片中文字出错时，可精简文字或更换模型后重画。

选择的比例为构图目标，实际像素尺寸由模型及尺寸参数决定。标准图片接口的自动尺寸为方形 1024×1024、竖版 1024×1536、横版 1536×1024；因此并不保证精确的 3:4 或 16:9 输出。

## 数据和模型资源

配置与作品都在应用的 `data/` 目录：

```text
data/
  config.json              # 本机模型设置，含明文 Key，文件权限 600
  trends.json              # 热榜缓存、14天热梗库、刷新设置与关注词，不含模型密钥
  projects/<作品编号>/
    project.json           # 原始素材、拆页方案、状态和记录
    prompts/               # 实际发送到生图模型的完整提示词
    images/                # 下载到本机的模型图片
```

后端只监听本机回环地址。保存过的 Key 不会回传给网页，也不会写入作品导出包。更换中转站域名时需要重新输入 Key。不要分享 `data/` 配置文件；该目录已列入 `.gitignore`。

素材和提示词会发送给你配置的模型服务，图片 URL 会由本机后端下载。应用没有托管服务器，没有内置 API Key，也不会自动使用聊天账号额度。

## 技术结构

- 前端：原生 HTML / CSS / JavaScript，创作对话、当下热点、作品记录、模型设置四个视图，同源调用后端。创作、预览、修改和下载统一在对话中完成。
- 后端：Node.js 内置 HTTP 服务、Fetch 与文件系统，无第三方运行依赖。
- 持久化：按作品保存 JSON，使用临时文件加原子替换写入。
- 任务：每个作品后台异步执行；图片逐张生成；最多两个作品任务同时运行。
- 热点：独立后台定时采集、失败保留缓存，同平台话题去重，关注词与定时设置保存在本机。测试可设 `TRENDS_AUTO_REFRESH=0` 禁止自动外部请求。
- 首版不包含多人账号、定时发布、拖拽画布、参考图上传与原生可编辑图层。
