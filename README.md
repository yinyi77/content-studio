# 图文创作工作台

面向个人使用的本地 Web 应用。配置 OpenAI 兼容中转站，即可完成「输入素材 → AI 拆页 → 修改方案 → 生成图片 → 下载作品」。

## 当前界面

2026-10-28 已将获认可的「现代编辑部」视觉接入正式工作台：顶部导航、纸白与朱砂色、宋体标题、横向页面序列，以及可切换的「视觉预览／内容大纲」。正式地址仍为 http://127.0.0.1:4318/ 。

图像生成的六种风格仍完整保留在原生下拉框中：手绘知识、杂志编辑、温暖生活、醒目海报、工程蓝图、极简留白。界面配色不会覆盖所选生成风格；模型配置、历史记录和 API 后端均沿用原实现。

仓库仅包含应用源码与必要文档，不包含个人模型配置、生成记录、本地界面备份和验证截图。首次启动后，在页面中填写自己的模型配置。

## 启动

需要 Node.js 20 或更新版本，无需安装 npm 依赖。

```bash
cd content-studio
npm start
```

上面的 `content-studio` 替换为实际克隆目录。浏览器打开 http://127.0.0.1:4318 。macOS 也可在终端执行 `./启动工作台.command`。按 Ctrl+C 停止。

如果端口被占用，可以运行 `PORT=4319 npm start`，然后访问对应端口。

## 首次配置

打开「模型设置」，分别填写文字和生图模型：

- **Base URL**：例如 `https://你的中转站域名/v1`。保留服务商指定的 API 前缀；不要填写中转站管理页面地址。
- **模型名称**：填写中转站实际开放的模型 ID。可以手动填写，也可保存后读取模型列表。
- **API Key**：在本地界面输入，不需要发到聊天里。两种模型可使用同一站点、同一 Key。
- **生图协议**：标准图片接口选 `Images`（`/images/generations`）；中转站通过聊天接口返回图片时选 `Chat`（`/chat/completions`）。
- **图片尺寸**：默认自动选择常见横竖尺寸；模型不接受时，按接口文档选择明确尺寸。

保存配置后可进行连接测试。文字测试会真实调用一次文字模型；生图测试会真实生成一张图片，可能产生费用。读取模型列表不代表模型一定可调用。

支持图片返回形式：Images 的 `data[].b64_json` / `data[].url`；Chat 的 `message.images`、图片 content 数组、Markdown 图片和图片 Data URL。不支持异步提交任务再轮询的专有生图协议；若中转站采用该方式，需要增加适配器。

## 使用

1. 在「创作台」粘贴主题、原始素材或文章，选择多页图文／信息图／封面、风格、目标比例和页数。
2. 点击分析。文字模型生成标题、发布文案及每一页的图上文字和画面描述。
3. 编辑并保存方案；确认内容后点击生成。图片逐页保存，失败时显示原因。
4. 可以只重试失败页、重新生成指定页、下载单张图片，或打包下载图片、文案和提示词。
5. 「作品记录」可重新打开历史任务。刷新浏览器不会丢失任务；重启服务后中断任务需手动继续，不会自动重复付费调用。

修改某页的图上文字或画面描述后，原图会从当前方案中失效，需要重新生成该页。不同页面的风格通过统一视觉参考与提示词保持；首版未实现跨页参考图锁定。图片中文字出错时，应改少文字或更换模型后重新生成。

选择的比例为构图目标，实际像素尺寸由模型及尺寸参数决定。标准图片接口的自动尺寸为方形 1024×1024、竖版 1024×1536、横版 1536×1024；因此并不保证精确的 3:4 或 16:9 输出。

## 数据和模型资源

配置与作品都在应用的 `data/` 目录：

```text
data/
  config.json              # 本机模型设置，含明文 Key，文件权限 600
  projects/<作品编号>/
    project.json           # 原始素材、拆页方案、状态和记录
    prompts/               # 实际发送到生图模型的完整提示词
    images/                # 下载到本机的模型图片
```

后端只监听本机回环地址。保存过的 Key 不会回传给网页，也不会写入作品导出包。更换中转站域名时需要重新输入 Key。不要分享 `data/` 配置文件；该目录已列入 `.gitignore`。

素材和提示词会发送给你配置的模型服务，图片 URL 会由本机后端下载。应用没有托管服务器，没有内置 API Key，也不会自动使用聊天账号额度。

## 技术结构

- 前端：原生 HTML / CSS / JavaScript，三个视图，同源调用后端。
- 后端：Node.js 内置 HTTP 服务、Fetch 与文件系统，无第三方运行依赖。
- 持久化：按作品保存 JSON，使用临时文件加原子替换写入。
- 任务：每个作品后台异步执行；图片逐张生成；最多两个作品任务同时运行。
- 首版不包含多人账号、定时发布、拖拽画布、参考图上传与原生可编辑图层。

## 与 baoyu-skills 的关系

本项目是独立的 Web 适配实现，真实复用 `baoyu-skills` 的内容分析、提示词组织和六套风格参考。没有运行完整的官方 Agent 工作流，也不属于官方 GUI。

上游仓库：https://github.com/JimLiu/baoyu-skills

固定版本及文件清单见 `vendor/baoyu-skills/SOURCE.json`，原 MIT 许可证见 `vendor/baoyu-skills/LICENSE`。修改上游提示词前建议保留版本记录。模型服务及其生成内容按对应服务条款使用。
